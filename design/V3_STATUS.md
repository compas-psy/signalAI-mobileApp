# SignalAI v3 — что реализовано и что осталось

Отчёт по ТЗ `SignalAI-Design-Spec-v3.md` + `AGENT_IMPLEMENTATION_SPEC.md`.
Формат по §23: что сделано, чем проверить, какие ограничения остались.

---

## Реализовано

### Фаза 1 — книга капитала (фундамент)

| Что | Где | Проверка |
|---|---|---|
| Деньги в фиксированной точке (`Money`, `Quantity`, `Currency`) | `domain/ledger/money.dart` | `test/capital_ledger_test.dart` |
| Неизменяемые события книги, 15 типов операций | `domain/ledger/ledger_event.dart` | там же |
| Хранилище только на дозапись, версия схемы, дедуп по id | `data/ledger/ledger_store.dart` | там же |
| Детерминированные проекции: остатки, лоты FIFO, позиции, P&L | `domain/ledger/projections.dart` | там же |
| Разбор выписки Т-Инвестиций в события | `data/ledger/broker_import.dart` | там же |

**31 тест финансовой корректности**: частичные продажи, FIFO по нескольким
лотам, шорт и разворот одной сделкой, фандинг в обе стороны, вармаржа,
валюта без курса, порядок событий, корректировка без стирания истории,
повторный импорт выписки.

Ключевые решения:

- **`double` для денег запрещён.** `0,1 + 0,2` в двоичной плавающей точке даёт
  `0,30000000000000004`; на тысяче операций баланс перестаёт сходиться.
- **Разные валюты не складываются** — падает с ошибкой, а не превращается в
  «105 непонятно чего».
- **Порядок применения — по времени операции**, а не по порядку записи в файл:
  запоздавший импорт встаёт на своё место и не портит историю.
- **Снимок брокера не переписывает книгу**, а создаёт наблюдение сверки: иначе
  сбой площадки молча стирал бы историю владельца.
- **Неизвестный тип операции не подгоняется под похожий**: попадает в книгу
  корректировкой с исходным описанием. Молчаливое «всё остальное — комиссия»
  однажды превратило бы дивиденд в издержку.

### Фаза 2 — каркас v3

- Пять разделов: **Сегодня · Капитал · Торговля · Лаборатория · Контроль**;
  подразделы — пилюли в шапке, глубина максимум два уровня.
- Миграция маршрутов версии 2 (`AppRoute.fromLegacy`), тесты в
  `test/navigation_test.dart`.
- Шапка раздела: заголовок, время данных, чип режима риск-движка
  (NORMAL / CAUTION / REDUCE ONLY / KILL SWITCH) — индикатор, а не переключатель.
- Аварийная остановка отдельной красной кнопкой в рейле планшета.
- Токены v3: `border #24242B`, `textMuted #9696A1`, `textFaint #666670`,
  `info #63A5FF`, `tactical #B38CFF`, `warning #FFB74D`. Семантика строгая:
  жёлтый — только действие.

### Экран «Сегодня»

Всё из настоящих чисел книги: совокупный капитал, внесено и результат,
полоса аллокации по контурам факт против цели, свободный кэш, стоимость
позиций, нереализованный и чистый результат, разложение «из чего результат»
расходящимися барами, здоровье данных, кнопка сверки.

**Очередь решений** собирается из фактического состояния: неподтверждённые
идеи, расхождения книги, книга без диска, позиции без стопа (первыми — это
дефект). Пустая очередь объясняет, почему она пуста.

### Раздел «Капитал»

- **Обзор** — внесено, стоимость, реализовано, нереализовано; доходы,
  издержки, разрез по валютам и контурам.
- **Счета** — карточка на счёт: тип, валюта, остаток, статус сверки, время
  синхронизации, права ключа. Право на вывод не запрашивается, и это написано.
- **Пакеты** — целевые корзины; ожидаемая доходность не показывается, пока её
  нечем подтвердить.
- **Книга** — фильтры (все · сделки · деньги · доходы · издержки · правки),
  разбор операции до идентификатора, **ручной ввод операции** и заведение
  счёта. Знак задаёт тип: вывод не может быть положительным.
- **Аналитика** — результат, издержки, честная оговорка про TWR/XIRR.

### Торговый цикл

- **Влияние на портфель** в шите подтверждения: каким станет открытый риск в
  процентах капитала, сколько сделок будет одновременно, есть ли позиция той
  же группы корреляции. Подход к лимиту (80%) предупреждает.
- После подтверждения запускается сверка, а не запись «на всякий случай»:
  заявка — ещё не позиция.
- **Импорт выписки** Т-Инвестиций наполняет книгу сам.

## Осталось

| Что | Почему не сделано |
|---|---|
| **Опционы** (payoff, греки, IV rank, конструкции) | Нужна реальная цепочка опционов и греки из Invest API. Диаграмма выплат по выдуманным премиям — обман, а не заглушка; раздел показывает причину |
| **TWR / MWR (XIRR)** | Требуют стоимости капитала на даты потоков. Появятся, когда книга накопит историю за несколько периодов; пока показан простой процент с оговоркой, что он занижает результат при поздних пополнениях |
| **Журнал сделок**: дисциплина плана, MAE/MFE, версии плана | Нужна связка Trade → Order → Fill поверх книги; сейчас журнал бумажных сделок работает по-старому |
| **Импорт выписки Bybit** | Разобран путь Т-Инвестиций; у Bybit другой формат истории исполнений |
| **Кривая капитала во времени** | Проекция на даты уже есть (`project(asOf:)`), нужен обход дат и кэш |
| **AI Copilot** | Отдельная фаза; требует контракта «ответ только со ссылкой на источник» |
| **Ребалансировка пакетов** | Нужен предпросмотр сделок под подтверждение |

## Отступление от ТЗ, о котором нужно знать

ТЗ требует SQLite (предпочтительно Drift). Реализовано хранилище
**журналом только на дозапись** (NDJSON с версией схемы), и вот почему:

1. Книга по модели неизменяема — `UPDATE` и `DELETE` в ней быть не должно.
   Файл-журнал выражает это точнее, чем таблица, где они возможны.
2. Миграции сводятся к версии схемы в заголовке, транзакция — к атомарной
   дозаписи; временный файл плюс переименование при полной перезаписи.
3. Не появляется нативной зависимости (`sqlite3`) в приложении, которое
   подтверждает сделки: это ещё одна поверхность отказа на устройстве
   владельца, а проверить её сборку на этом устройстве нечем.

Хранилище спрятано за интерфейсом: если книга вырастет до сотен тысяч
операций и линейный разбор станет заметен, замена на SQLite не затронет
домен и экраны.

## Как проверить руками

1. **Сегодня** → «Сверить с площадками»: если ключи Т-Инвестиций заданы,
   в книгу импортируется выписка за год, появляются счета и позиции.
2. **Капитал → Книга** → «Записать операцию»: заведите начальный остаток —
   капитал, аллокация и «Из чего результат» пересчитаются сразу.
3. **Капитал → Книга** → тап по строке: разбор до идентификатора, ссылки
   брокера и статуса сверки.
4. **Торговля → Идеи** → идея → «Отправить на биржу»: в шите виден блок
   «Влияние на портфель».
5. **Контроль**: четыре подраздела вместо одной ленты настроек.
