# Ключи и секреты SignalAI

## Главное правило

**В мобильном приложении ключей нет.** Ни одного. Приложение ходит только в свой
мобильный гейтвей (Server B) с токеном устройства и получает уже готовые сигналы
(ТЗ §2, §11). Все ключи бирж, брокера и ботов живут на сервере.

Отсюда следствие: секреты ниже прописываются **в репозитории бэкенда** (или в
`.env` на самом сервере), а не в этом репозитории. В этом репозитории нужны
только два секрета — подпись Android и адрес гейтвея.

Куда прописывать в GitHub:
`Settings → Secrets and variables → Actions → New repository secret`.

Для боевых ключей лучше `Settings → Environments → production` с
«Required reviewers» — тогда workflow не сможет прочитать их без вашего
подтверждения.

## 1. Российские фьючерсы — Т-Инвестиции (T-Invest API)

Токен создаётся в приложении/личном кабинете Т-Инвестиций:
профиль → «Настройки» → «Токены для API».

| Имя секрета | Что это | Права |
|---|---|---|
| `TINVEST_TOKEN` | токен для **анализа**: свечи, стакан, инструменты, ГО | **только чтение** |
| `TINVEST_TRADE_TOKEN` | токен для **исполнения**: выставление bracket-ордеров | полный доступ |
| `TINVEST_ACCOUNT_ID` | идентификатор брокерского счёта | — |
| `TINVEST_SANDBOX` | `true` на время обкатки (песочница) | — |

Почему два токена: аналитика крутится постоянно и по всей вселенной
инструментов — ей нельзя давать право торговать. Торговый токен использует
только модуль исполнения, после вашего подтверждения (ТЗ §7).

Отдельно: исторические свечи и OI по FORTS берутся из **MOEX ISS** — это
публичный API, ключ не нужен (ТЗ §3.1).

## 2. Крипта — Bybit

Ключи создаются в Bybit: `API` → `Create New Key` → System-generated.

| Имя секрета | Что это | Права |
|---|---|---|
| `BYBIT_API_KEY` | ключ | Read-Only |
| `BYBIT_API_SECRET` | секрет к нему | Read-Only |
| `BYBIT_TRADE_API_KEY` | ключ для исполнения | Read + **Trade** |
| `BYBIT_TRADE_API_SECRET` | секрет к нему | Read + Trade |
| `BYBIT_TESTNET` | `true` для testnet | — |

Обязательно при создании ключа:

* **не включать право вывода средств** (Withdraw) — никогда, ни на одном ключе;
* включить **IP-whitelist** и вписать IP сервера B;
* срок жизни ключа — максимальный, но с напоминанием о ротации.

Публичные рыночные данные Bybit (свечи, OI, funding, тикеры) отдаются **без
ключа** — на первом этапе (ТЗ §14, этап 1) аналитика по крипте заводится вообще
без секретов. Ключ нужен только для баланса и исполнения.

## 3. Telegram-бот

Бот создаётся у `@BotFather` → `/newbot`.

| Имя секрета | Что это |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен вида `123456789:AA…` |
| `TELEGRAM_CHAT_ID` | ваш chat_id (узнать: написать боту и открыть `https://api.telegram.org/bot<TOKEN>/getUpdates`) |

По ТЗ §8 подтверждение сделок в Telegram по умолчанию **выключено** — бот
работает на чтение и на стоп-действия (`/positions`, `/pnl`, `/pause`,
`/killswitch`). Это защита на случай угона аккаунта Telegram.

## 4. MAX-бот

Бот создаётся у `@MasterBot` в MAX, токен выдаётся там же.

| Имя секрета | Что это |
|---|---|
| `MAX_BOT_TOKEN` | токен бота MAX |
| `MAX_CHAT_ID` | идентификатор личного чата |

MAX подключается тем же интерфейсом `NotifierAdapter`, что и Telegram (ТЗ §8),
и дублирует утренний дайджест.

## 5. LLM-аналитик

| Имя секрета | Что это |
|---|---|
| `ANTHROPIC_API_KEY` | ключ Claude API для второй ступени анализа (ТЗ §5.2) |

Бюджет — не более 20 вызовов в день, кэш по (инструмент, дата, хеш данных).

## 6. Секреты этого репозитория (мобильное приложение)

| Имя секрета | Что это |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | keystore подписи в base64 (см. `docs/ANDROID_SIGNING.md`) |
| `ANDROID_KEYSTORE_PASSWORD` | пароль хранилища |
| `ANDROID_KEY_PASSWORD` | пароль ключа |
| `ANDROID_KEY_ALIAS` | `signalai-upload` |
| `SIGNALAI_API_BASE_URL` | `https://…` — адрес мобильного гейтвея Server B |

Никаких биржевых ключей здесь быть не должно: всё, что попадает в сборку через
`--dart-define`, лежит в APK открытым текстом и вынимается из него за минуту.

## Чего делать нельзя

* Класть ключи в код, в `.env` внутри git, в `--dart-define` мобильной сборки.
* Давать любому ключу право **вывода средств**.
* Держать один ключ и для аналитики, и для торговли.
* Присылать ключи в переписку или в issue — секрет, попавший в чат, считается
  скомпрометированным и подлежит немедленной ротации.

Если ключ утёк: отозвать в кабинете биржи/брокера → создать новый → обновить
секрет в GitHub → перезапустить сервис. Для Telegram — `/revoke` у BotFather.
