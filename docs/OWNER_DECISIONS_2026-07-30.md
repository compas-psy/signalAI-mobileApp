# Решения владельца от 30.07.2026 — дополнение к engine-ТЗ v1.02

Зафиксировано с живой сборки. Три решения меняют серверную работу; клиент к
ним уже готов.

## 1. Портфель: никаких шаблонов

Заготовленные пакеты (LQDT/ОФЗ/акции по типовым долям) удалены из
приложения. Пакет обязан **собираться движком**: комбинированный
фундаментально-технический отбор инструментов, оптимизация состава
современными статистическими методами, проверка на истории — по книге и
горизонту владельца, а не «как у всех».

Планка для портфельного контура сервера (эндпоинты §23 уже названы в ТЗ:
`/portfolio/models/recalculate` и далее):

- отбор кандидатов: фундаментальный срез (мультипликаторы, качество
  прибыли) × технический (режим рынка, структура);
- оптимизация состава с честной оценкой ошибки: ресемплинг/бутстрап вместо
  единственной точки в духе Марковица, усадка ковариаций, ограничение
  оборота;
- walk-forward и стресс-срезы обязательны; ожидаемая доходность на экране
  не показывается, пока не подтверждена вне выборки — показывается история;
- у каждого инструмента kill-condition, у пакета — правило пересмотра.

## 2. График идеи обязан нести разметку сделки

Диапазон и метки Вайкоффа, прайс-экшн, блоки и уровни смарт-мани, трендовые
линии — то, из чего собрана идея, должно быть видно на графике.

Состояние: сервер это **уже строит** (`pipeline/presentation.py`,
`build_annotations` — §9.1 в исполнимом виде), клиент **уже рисует**
(`TradeChart` + слои). Разрыв был в дырке между ними: лента `/ideas/today`
отдаёт сводки без разметки, плана и доказательств, а полную карточку
`/ideas/{id}` приложение не запрашивало. Починено на клиенте: открытие идеи
догружает полную карточку и подменяет сводку.

Серверу остаётся следить, чтобы детекторы заполняли `marks` у показаний —
пустые `annotations_json` при непустой оценке считаются дефектом пайплайна.

## 3. Статистическая обработка сделок + поле для экспериментов

Каждая идея проходит матстатистическую проверку (в ТЗ уже есть: probability
по тройному барьеру, calibration, OOS-гейты §19). Дополнение владельца: при
этой строгости должно оставаться **поле для экспериментов** — место, где
гипотеза живёт до того, как заработала статистическую значимость.

Практически:

- у идеи/стратегии есть признак «экспериментальная»: показывается отдельно,
  торгуется только на бумаге, в общий скоринг не подмешивается;
- эксперимент получает те же метрики (expectancy, PF, калибровка), что и
  боевые стратегии, — иначе его не с чем сравнить;
- перевод из эксперимента в бой — только через гейт §19, автоматических
  повышений нет.

Клиентская часть: журнал уже считает разрезы по стратегиям; когда сервер
начнёт помечать экспериментальные, лента разведёт их бейджем.

## Показанное состояние (для следующей сессии)

- Лента: лучшая идея на инструмент (клиентский отбор до серверного
  ранжирования по вероятности), тикер + имя актива, мини-график цены.
- Разбор: полная карточка догружается с `/ideas/{id}` — план, тезис,
  доказательства, разметка.
- Портфель: карточка «считает движок» вместо шаблонов.
